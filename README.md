# BlueCode

Терминальный мессенджер по Bluetooth Classic (RFCOMM/SPP) для Linux.
Без интернета и без сервера: два ноутбука рядом — и можно переписываться.

```
bluecode
```

```
  1 - showonline
  2 - mysettings
  3 - quit_n_stop_be_scanned
me = player228
>
```

## Установка

На старте `bluecode` печатает случайный ASCII-баннер (один из восьми) и
подстраивает его под ширину и высоту терминала. Отключить: `BLUECODE_NO_ART=1`.

### Ubuntu с нуля

```bash
sudo apt update
sudo apt install -y git python3 python3-venv bluez
git clone https://github.com/JustAWall/BlueCode.git
cd BlueCode
make install
bluecode
```

Если `make` нет — то же самое вручную:

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
```

### Первое соединение

MAC-адреса не нужны. Нажми `1` — BlueCode просканирует эфир и покажет **ники**:

```
me = printer
  0 - B4ck at menu
  1 - BlueCodeUser1
  2 - BlueCodeUser2
```

Дальше `chat 2`. Второй видит `... want to talk with you. Accept? [y/n] (y):`,
жмёт Enter — чат открыт.

Список — это только Bluetooth **Classic** устройства (BR/EDR), поэтому
BLE-шумиха от телефонов и часов туда не попадает. Из найденных BlueCode
пробует по очереди, кто ответит `hello` — остальные молча отбрасываются.

> **Единственный ручной шаг — pairing, один раз на пару устройств.**
> При `chat N` BlueCode спарит и доверит (`trust`) устройства сам, без
> `bluetoothctl`. Что увидишь:
>
> - на **Linux с BlueZ** обычно ничего — Just Works проходит молча;
> - на **Android/Windows** собеседник увидит запрос «Сопрячь с …?» — надо
>   нажать «Да»; если показан код, он одинаковый на обоих экранах;
> - если pairing не удался, BlueCode напишет причину по-человечески
>   («device is off, out of range», «confirm the request on the other
>   device») вместо `cannot reach peer`.
>
> MAC собеседника никуда пересылать не нужно: он приходит из скана.
> Ручной путь остаётся запасным:
> ```bash
> bluetoothctl pair AA:BB:CC:DD:EE:FF   # MAC собеседника
> bluetoothctl trust AA:BB:CC:DD:EE:FF
> bluetoothctl info AA:BB:CC:DD:EE:FF | grep -E "Paired|Trusted"
> ```

> Канал должен совпадать на обеих сторонах — `mysettings` → `channel`,
> по умолчанию 3.

Нужен работающий BlueZ и Bluetooth-адаптер; `bluecode` поднимет
сервис/адаптер сам, если сможет. Python ≥ 3.11; RFCOMM берётся из
стандартной библиотеки (`AF_BLUETOOTH`), поэтому PyBluez не нужен.

## Запуск без Wi-Fi

Команда `bluecode` доступна глобально (`~/.local/bin/bluecode`). Она сама:

1. проверяет Bluetooth и при необходимости поднимает его
   (`rfkill unblock`, `systemctl start`, `power on`);
2. при первом запуске спрашивает ник и сохраняет его;
3. открывает RFCOMM-канал и включает `discoverable` — тебя видно другим;
4. при выходе выключает `discoverable` (`quit_n_stop_be_scanned`).

Если автоподъём не удался (polkit требует пароль), будет честное сообщение
с командами, которые надо выполнить вручную.

Wi-Fi не нужен вообще: BlueCode открывает `AF_BLUETOOTH`/`BTPROTO_RFCOMM`
(семейство 31), IP-сети не касается. Проверено: в коде нет ни `AF_INET`,
ни HTTP-клиентов.

Единственное, что требует интернета — **один раз** поставить зависимости
(лаунчер сделает это сам при первом старте). Дальше можно выключить Wi-Fi
и работать в поле.

На обеих машинах:

```bash
bluecode
```

Одна машина пишет `chat N`, вторая видит приглашение. Всё.

**Про дальность:** Classic Bluetooth Class 2 — это ~10 м на открытом воздухе,
но 5–7 м через одну стену, и заметно меньше через бетон/металл. Если связь
рвётся — это не потеря пакетов, а разрыв RFCOMM-линка: в чате появится
`* peer connection lost`, вернёшься в меню и переподключишься. Для 5–10 м
в одной комнате запас большой, чат на таких дистанциях стабилен.

Полезно перед встречей: `bluetoothctl info <MAC>` должен показать
`Paired: yes` и `Trusted: yes`. Без pairing соединение отклоняется на уровне
ядра, и BlueCode честно скажет, что пир недоступен.

## Как это работает

- **Транспорт:** RFCOMM-сокет на фиксированном канале (по умолчанию 3).
  Обе стороны и слушают, и умеют подключаться — кто первый позвал, тот клиент.
- **Протокол:** кадр = `uint32` длина + JSON, максимум 64 КиБ. Кадры:
  `hello`, `hello_ack`, `invite`, `invite_reply`, `msg`, `typing`, `bye`.
  Неизвестные типы игнорируются, так что старые клиенты не падают от новых.
- **Присутствие:** broadcast в Classic Bluetooth не существует. Поэтому
  `showonline` пингует известных пиров из кэша (`~/.local/share/bluecode/peers.db`)
  параллельно с таймаутом 2 с; если никого — сам делает BR/EDR inquiry
  (8 с) и пробует всех, кто ответил. Устройство должно быть discoverable.
- **Печать:** `Enter` — отправить, `Shift+Enter` (или `Alt+Enter`) — перенос строки,  `Ctrl+Q` — выйти. Можно вставить многострочный код: текст уходит целиком,
  отступы и пустые строки сохраняются. Входящее сообщение печатается **над**
  строкой ввода, черновик не затирается. `Ctrl+C` очищает набранное.

  Почему `Shift+Enter` работает не во всех терминалах: это не отдельная клавиша,
  а escape-последовательность (`ESC[13;2u` в CSI-u или `ESC[27;2;13~` в
  modifyOtherKeys). `prompt_toolkit` не знает эти последовательности (вторую
  вообще считает обычным Enter), поэтому BlueCode регистрирует их сам и мапит
  на F24. Если твой терминал не отправляет Shift+Enter вовсе — используй
  `Alt+Enter`, это работает всегда.
- **Инвайт:** приходит даже если ты в меню. Enter = accept (по умолчанию `y`).
  Если занят другим чатом — приходит `busy`. Оба нажали `chat` одновременно —
  приходит `collision`, просто попробуй ещё раз.

## Подготовка двух машин

Обычно ничего делать не нужно: запусти `bluecode` на обеих машинах, `1`,
`chat N`. Pairing BlueCode выполнит сам.

Если хочешь спарить заранее (или автоматика не сработала):

```bash
bluetoothctl
[bluetooth]# power on
[bluetooth]# pairable on
[bluetooth]# discoverable on
[bluetooth]# scan bredr on     # найди MAC собеседника
[bluetooth]# pair AA:BB:CC:DD:EE:FF
[bluetooth]# trust AA:BB:CC:DD:EE:FF
[bluetooth]# scan bredr off
```

> `bluecode` держит `discoverable-timeout 0`, пока работает, и возвращает
> 180 при выходе. Без этого BlueZ гасит видимость через 3 минуты и тебя
> перестают находить.

Затем на обеих машинах:

```bash
bluecode        # запускает листенер и включает discoverable
```

`1` → список онлайн → `chat N`, либо сразу `chat <MAC>`.

**Канал должен совпадать** на обеих сторонах (`mysettings` → `channel <1-30>`,
потом перезапуск). Канал 3 обычно свободен; если занят — возьми другой.

## Где лежит состояние

| Что | Путь |
|---|---|
| настройки (ник, канал) | `~/.config/bluecode/config.json` |
| кэш пиров | `~/.local/share/bluecode/peers.db` |
| история ввода | `~/.local/share/bluecode/history-*.txt` |

Launcher — `~/.local/bin/bluecode` (переустановить: `make install`,
удалить: `make uninstall`). Он сам создаёт `.venv` при первом запуске,
так что после `make install` ничего дополнительно ставить не нужно.

Ник очищается от управляющих символов и ANSI-последовательностей: его
печатает собеседник, и `\x1b[…` не должен перекрашивать его терминал.

## Платформы

| Платформа | Статус |
|---|---|
| Ubuntu / Debian / Arch (BlueZ) | ✅ работает (`sudo apt install bluez`) |
| Termux (Android) | ❌ не работает: Android запрещает приложениям raw RFCOMM-сокеты, BlueZ нет. Нужен отдельный BLE-бэкенд через Android API |
| macOS / Windows | ❌ нет `AF_BLUETOOTH` |
| WSL | ❌ Bluetooth-адаптер не пробрасывается |

На Ubuntu:

```bash
sudo apt install python3 python3-venv bluez
cd BlueCode && make install
bluecode
```

Разница с Arch только в установке пакетов; сам код — стандартная библиотека.

## Если цвета ломаются

`bluecode` сам выключает цвета, когда вывод идёт не в терминал (пайп,
`tee`, лог), и уважает `NO_COLOR=1`. Если видишь `?[1m` вместо жирного
текста — это значит, что какой-то враппер экранирует ANSI; запусти
напрямую из терминала.

Внутри `mysettings` выход — `back`, `0`, `3` или `q` (как и в главном меню).

## Ограничения (честно)

- **Linux only** — используется `AF_BLUETOOTH` из ядра.
- Нужно **спаривание** — но делает его BlueCode сам при первом `chat`.
- **Нет шифрования на уровне приложения**: защита — та, что даёт pairing
  (link key). Для «два ноутбука на кухне» нормально; для паранойи нужен
  X25519 + AEAD поверх протокола (не реализовано).
- `showonline` медленный при холодном старте: inquiry занимает секунды.
- Loopback на одном адаптере ядро не поддерживает — для теста нужны две машины.
  Поэтому протокол и state machine покрыты тестами через `socketpair`.
